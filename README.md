# 阿里云 CDT 流量守护（aliyun-cdt-guard）

监控阿里云 **CDT（云数据传输）公网出流量**，在流量或费用失控前**自动关机止损**，
并每天推送一份使用报表。

> 适合人群：用阿里云小磁盘/抢占式实例跑服务、担心流量超额扣费的用户。

---

## ⚠️ 先读这一段：这个仓库里有两个版本

| 版本 | 位置 | 能自动止损 | 能自动开机 |
|---|---|---|---|
| **服务器版**（本 README 下方描述的那套） | 根目录 `install.sh` | ✅ | ❌ **做不到** |
| **Cloudflare 版**（推荐） | `worker/` 目录 | ✅ | ✅ |

### 为什么服务器版开不了机

它把机器人**装在被监控的机器自己身上**，于是有个解不开的死锁：

```
服务器流量超标 → 脚本把自己关机了（省钱 ✅）
              → 但脚本自己也一起死了
              → 下个月流量重置，没人去开机（复活 ❌）
```

**要去叫醒一扇门里的人，你得站在门外。**

### 该用哪个

- **想省心、要真正的「关机后自动复活」** → 用 **Cloudflare 版**：
  见 [`worker/README.md`](./worker/README.md) 与 [`worker/部署指南.md`](./worker/部署指南.md)，
  部署一条命令 `bash deploy.sh`，免费额度完全够用。
- **只想要「超标自动关机止损」这一半功能** → 服务器版够用，继续往下读即可。

## 服务器版：它能帮你解决什么

- **忘了看流量，月底被扣一笔大的** —— 脚本每 5 分钟检查一次，超过你设的阈值立刻关机。
- **不知道钱花在哪了** —— 每天早上 9 点推送报表：流量用了多少、本月账单多少、账户还剩多少钱。
- **机器悄悄掉线了却不知道** —— 实例从「运行中」变成「已停止」的那一刻立刻通知你。
- **账户快没钱了还蒙在鼓里** —— 余额低于警戒线就告警，欠费时升级为红色告警。
- **手机上就能管机器** —— Telegram 机器人菜单，点按钮查流量、看报表、开关机、暂停监控。

> ❌ 做不到：**「下个月流量重置后自动开机」** —— 这是本版架构上的死结，
> 详见上方说明。要这个功能请用 Cloudflare 版。

## 推送给你的都有什么

### 自动告警（定时巡检触发）

| 级别 | 事件 | 说明 |
| --- | --- | --- |
| 告警 | 流量超标已止损 | 流量超阈值，已强制关机 |
| 告警 | 止损关机失败 | **需要你立刻手动处理** |
| 告警 | 开机失败 / 开机未成功 | 通常为库存不足，脚本会自动重试 |
| 告警 | 监控异常 | 连续 3 次查不到数据，监控「失明」了 |
| 告警 | 账户已欠费 | 余额为负，实例随时可能被停机 |
| 提醒 | 实例已停止 | 从「运行中」掉到「已停止」，若非你主动操作要留意 |
| 提醒 | 流量超标提醒 | 已超标且保持关机中，每天提醒一次 |
| 提醒 | 流量阈值高于免费额度 | 省钱预警：你的阈值超出免费额度了 |
| 提醒 | 免费额度即将用尽 / 已用尽 | 用量达免费额度 80% / 95% 时各提醒一次 |
| 提醒 | 账户余额过低 | 余额低于你设的警戒线 |
| 提醒 | 本月账单超支 | 账单超过你设的警戒线 |
| 正常 | 已恢复运行 | 自动开机成功 |

### 定时报表

每天早上 9:00 推送：每台机器的状态 / 公网 IP / 规格 / 流量占用 / 免费额度剩余 / 本月账单 / 账户余额。

### 随时可查（手机菜单）

- **📅 周报** —— 最近 7 天流量趋势，含区间新增量与日均用量。
  数据来自本地台账，巡检每 5 分钟记录一次、按天去重。
- **💰 余额详情** —— 逐账号显示账户余额、本月账单、免费额度占用百分比。
  同一账号下多台机器只查一次接口，节省调用次数。
- **🏦 账号汇总** —— 按账号（AccessKey）分组看总账：每个账号下有几台机器、
  本月总共用了多少、还剩多少额度。配了 2 个以上账号时，报表末尾也会自动附加这一段。

### 三级菜单结构

菜单分三层，点进去之后再点按钮继续往下：

| 层级 | 内容 | 说明 |
| --- | --- | --- |
| 第一层 | 主菜单（上面那张） | 功能总入口 |
| 第二层 | 实例列表 | 点「⚙️ 单机操作」进入，每台机器一个按钮 |
| 第三层 | 单机操作 | 点某台机器进入，可对它查状态 / 开机 / 关机 / 暂停 |

第三层长这样：

```
┌─────────────────────────────────────────────┐
│  菲律宾节点                                  │
│  当前: 监控中                                │
│                                             │
│  [ 📊 状态 ]        [ 🚀 开机 ]              │
│  [ 🛑 关机 ]        [ ⏸️ 暂停监控 ]          │
│  [ 🔙 返回列表 ]     [ 🏠 返回主菜单 ]        │
└─────────────────────────────────────────────┘
```

> **为什么「暂停监控」按钮会变成「恢复监控」？**
> 因为菜单是随状态重绘的。暂停之后按钮文字就变成「▶️ 恢复监控」，
> 一眼就能看出这台机器当前不在自动管理。

| --- | --- |

| `/accounts` | 按账号汇总所有机器的额度占用 |
| `/weekly` | 查看最近 7 天流量周报 |

### 几点说明

- **按钮等于替你打一句话。** 底部菜单用的是 Telegram 的「回复键盘」，
  点按钮等于发一条文字消息，机器人再按这句话执行动作。
  所以你既可以直接点按钮，也可以手打「总览」两个字，效果一样。
- **只有你能操作。** 机器人只响应配置里那个 Chat ID，别人发消息不会有任何反应，
  也不会触发任何开关机动作。这是硬性安全设计。
- **「暂停」只停自动管理。** 暂停后脚本不再自动开关机，但手动按钮仍然可用，
  自动止损（流量超标强制关机）也照常执行。批量操作也会跳过已暂停的机器。
- **免费额度是按「账号」算的，不是按机器。** 同一个账号下的所有机器共享那一份额度。
  所以机器一多，逐台看流量容易误判 —— 「🏦 账号汇总」就是专门解决这个的：
  它按 AccessKey 把机器分组，每个账号只查一次接口（不能把每台的结果相加，会重复计数）。
- **配额表可能被转发，所以 AccessKey 会打码。** 汇总里只显示 AK 前 6 位加四个星号。
- **机器人崩了不影响止损。** 机器人是独立进程，和定时巡检完全解耦。
  就算它挂了，流量监控与自动止损依然正常工作。
- **同一个 Bot 只能开一个机器人进程。** 脚本内置了锁，重复启动会被拒绝，
  不会出现两个进程抢消息的问题。
- **界面全中文。** 菜单、回复、告警里都不会出现英文字母。

## 常用操作

## ⚠️ 先搞清楚免费额度：不是 10TB，是 200GB

这是最容易踩的坑，**务必读完再设阈值**。

阿里云 CDT 每月赠送的**免费公网流量**：

| 地域 | 免费额度 |
| --- | --- |
| 中国内地地域 | **20 GB / 月** |
| 非中国内地地域（中国香港、新加坡、菲律宾、日本、美国、欧洲等） | **200 GB / 月** |

两个关键点：

1. **按账号统一计算**，不是每台机器各有一份。账号内所有接入 CDT 的云产品共享。
2. **超过免费额度就开始按量计费**，不是"离得很远就免费"。

**为什么有人会以为有 10TB？**
阿里云 CDT 接口会返回一个 `HighestTraffic` 字段，值是 `10995116277760` 字节 = **10 TiB**。
那是**计费阶梯的第一档上界**（0–10TB 属于第一档单价），**和免费额度毫无关系**。
把阶梯上界当成免费额度，会严重高估可用流量。

> 本脚本已内置正确判断：按你的地域自动识别是 20GB 还是 200GB，
> 日报里会直接显示"免费额度剩多少"；若你把阈值设得高于免费额度，
> 巡检时会主动告警提醒你存在付费风险。

**建议阈值**：非中国内地填 `180`（留 20GB 缓冲）；中国内地填 `18`。

## 快速开始（3 步）

### 第 1 步：准备 AccessKey（不要用主账号）

1. 打开阿里云控制台 → 右上角头像 → **访问控制 RAM** → 用户 → 创建用户
2. 勾选「使用永久 AccessKey 访问」
3. 创建完成后**立刻复制** AccessKey ID 和 Secret（只显示一次）
4. 给这个子账号授予以下权限（够用即可，越少越安全）：
   - **自定义策略**（只能查实例、开机、关机，不能创建 / 删除机器）：
     在 RAM → 权限策略 → 创建权限策略 → 脚本编辑，粘贴
     [`docs/ram-policy-ecs-minimal.json`](docs/ram-policy-ecs-minimal.json) 的内容
   - `AliyunCDTReadOnlyAccess`（查流量，只读）
   - `AliyunBSSReadOnlyAccess`（查账单与余额，只读）

   ⚠️ 不要给 `AliyunECSFullAccess`，也不要用主账号的 AccessKey：
   这两种密钥一旦泄露，对方可以开新机器、删机器、改安全组，费用都记在你账上。

### 第 2 步：准备通知渠道

支持三个渠道，可同时启用，互不影响。

**主力渠道：Telegram（必配）**

1. Telegram 搜索 `@BotFather` → 发送 `/newbot` → 按提示创建机器人 → 复制 Token
2. Telegram 搜索 `@userinfobot` → 发送任意消息 → 复制它回复的数字 ID

**推荐自建渠道：NapCat / OneBot（可选）**

自己搭的 QQ 机器人，**无配额限制、无需审核，可以承担全部告警**。

1. 在任意一台常开机器上部署 NapCat（或 Lagrange / go-cqhttp）
2. 开启 HTTP 服务，记下地址（如 `http://127.0.0.1:3000`）和 Token
3. 填群号即可（私聊填对方 QQ 号）

**备选渠道：QQ 官方机器人（可选，仅日报）**

1. 打开 https://q.qq.com 注册并创建机器人
2. 管理端获取 `AppID` 和 `AppSecret`
3. 把机器人拉进群，群里 @ 它，从日志里拿到群的 OpenID

> **重要限制**：腾讯对 QQ 官方机器人**主动消息**有严格频控，群聊**每月仅 4 条**。
> 所以官方通道只发日报摘要，**告警不走这条路**。想用 QQ 收告警请用 OneBot 方案。

### 第 3 步：一条命令安装

SSH 登录你的服务器（任意能联网的 Linux），以 root 执行：

```bash
bash <(curl -sL https://raw.githubusercontent.com/yys9253462-gif/aliyun-cdt-guard/main/install.sh)
```

然后跟着中文提示走：粘贴 AccessKey → **从自动列出的实例里选一台** → 设流量阈值。
全程大约 3-5 分钟，装完会自动做一次自检并给你发一条测试通知。

> **不用自己找地域代码和实例 ID**：填完 AccessKey 后，脚本会自动查询你账号下
> **所有地域**的实例，连地域带实例 ID 一起列出来让你选。查不到时会退回手动填写，
> 手动列表已包含东南亚全部节点（菲律宾 `ap-southeast-6`、马来西亚、印尼、泰国等）。

## 配置项说明

配置文件位于 `/opt/cdt-guard/config.json`（权限锁定为 600）：

| 字段 | 说明 |
| --- | --- |
| `name` | 备注名，通知里用它标识机器 |
| `ak` / `sk` | RAM 子账号的 AccessKey |
| `region` | 实例所在地域，如 `cn-hongkong` |
| `instance_id` | ECS 实例 ID，形如 `i-xxxxxxxx` |
| `traffic_limit` | 流量熔断阈值（GB） |
| `balance_limit` | 余额过低警戒线。低于它就告警；填 `0` 关闭。默认 `10` |
| `bill_limit` | 本月账单警戒线。超过它就告警；填 `0` 关闭。默认 `0`（关闭） |
| `bill_endpoint` | 账单接口节点，国内站 / 国际站不同 |
| `currency` | 显示货币符号 |
| `resgroup` | 资源组 ID，RAM 权限收窄到资源组时才需要 |
| `paused` | 是否暂停监控 |

通知相关配置：

| 字段 | 说明 |
| --- | --- |
| `telegram.bot_token` | Telegram 机器人 Token（主力渠道） |
| `telegram.chat_id` | 你的 Telegram 数字 ID |
| `onebot.base_url` | NapCat / OneBot 的 HTTP 地址 |
| `onebot.token` | OneBot 访问 Token（没设可留空） |
| `onebot.target_id` | 群号或对方 QQ 号 |
| `onebot.target_type` | `group` 群聊 / `private` 私聊 |
| `qq.app_id` / `qq.app_secret` | QQ 官方机器人凭证 |
| `qq.target_id` | 群 OpenID 或用户 OpenID |
| `qq.target_type` | `group` 群聊 / `user` 单聊 |

## 工作原理

**两个独立进程，互不干扰：**

```
【进程一】定时巡检（每 5 分钟跑一次，跑完就退出）
        │
        ├─ 查 CDT 当月流量 ──┐
        │                    │
        └─ 查实例状态 ───────┤
                             ▼
                   流量 < 阈值？
                   ┌─────────┴─────────┐
                  是                    否
                   │                     │
         实例是 Stopped？          实例是 Running？
          ┌───┴───┐                ┌───┴───┐
          是      否               是      否
          │       │                │       │
       自动开机  不动          强制关机  保持关机
                                     │
                              发送告警通知

        另外每轮还会顺带检查：
          · 状态是否从「运行中」掉到「已停止」
          · 免费额度是否跨过 80% / 95%
          · 账户余额 / 本月账单是否越线

        并顺手记一条流量快照到本地台账（供周报统计）

        ⚠️ 关键前提：以上所有判断，**都要求脚本自己是活着的**。
           一旦「流量超标 → 强制关机」发生，脚本随机器一起停了，
           那个「自动开机」分支就**永远不会被走到**。
           这就是服务器版的死锁 —— 要真正的自动复活，
           请用 Cloudflare 版（worker/ 目录），它在门外。


【进程二】Telegram 机器人（常驻，一直在听）
        │
        └─ 收到你的消息 / 按钮点击
                │
                ├─ 校验来源是不是你本人（别人一律忽略）
                ├─ 翻译菜单文字 -> 对应动作
                │    · 一级菜单：按文字匹配功能
                │    · 二级菜单：按钮文字里带机器名
                │    · 三级菜单：用「最近选中的机器」会话状态
                ├─ 「账号汇总」按 AccessKey 分组，每个账号只查一次
                ├─ 执行对应操作（查询 / 开关机 / 暂停）
                └─ 把结果回复给你
```

**为什么机器人必须常驻，不能塞进定时任务？**
定时任务跑完就退出，没法「一直听着」你的消息。要让按钮点下去有反应，
就必须有一个进程始终连在 Telegram 上等消息 —— 这就是「长轮询」。

> **同一个 Bot 不能同时用长轮询和 Webhook**，也不能同时开两个轮询进程，
> 否则会互相踢下线、消息丢失。脚本用文件锁防止了后者。

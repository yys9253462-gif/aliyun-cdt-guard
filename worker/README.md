# CDT 流量守护 · Cloudflare Workers 版

把原来装在服务器上的流量守护机器人，搬到 Cloudflare 上运行。

## 为什么值得搬

原来的机器人**装在被监控的那台机器自己身上**，于是有个死结：

```
流量超标 → 脚本把自己关机了（省钱）
        → 脚本也一起死了
        → 下个月流量重置，没人去开机（复活不了）
```

搬到 Cloudflare 后：机器关了，机器人照样在跑 —— **它是唯一能把机器叫醒的东西**。

**成本：0 元。** 免费额度（每天 10 万次请求）远超实际用量（每天约 300 次）。

## 快速开始

```bash
# 一条命令走完：部署 + 自检 + 填机器清单，全程中文提示
bash deploy.sh
```

这一条命令会带你走 7 步：检查环境 → 登录 → 建存储 → 写密钥 → 上传代码
→ **自动自检** → **接着问你机器信息**。

```bash
# 事后想改机器清单
bash configure.sh          # 交互式填写（覆盖旧配置）
bash configure.sh show     # 只看当前配置
```

然后在 Telegram 对机器人发 `/menu`。

详细图文说明见 **[部署指南.md](./部署指南.md)**。

### 两个脚本的关系（重要）

`configure.sh` 有**两种用法**，靠文件末尾「是否被直接执行」的判断区分：

- 直接跑 `bash configure.sh` → 只做配置
- 被 `deploy.sh` 引用（`source`）→ 由对方调用 `run_configure()`，
  部署完接着问机器信息

**配置逻辑只有一份**（`run_configure()`），两边共用。之所以这样设计：
原来两边各有一份「问机器信息」的代码，早晚会走偏 —— 改了一处忘了另一处。

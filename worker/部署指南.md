# CDT 流量守护 · Cloudflare 部署指南

> 这份指南假设你**没写过代码**。每一步都写清楚了「做什么、为什么、看到什么算成功」。
> 遇到卡住的地方，把屏幕上整段内容发给我就行。

## 先搞清楚：这次装的是什么，为什么值得装

### 你原来那套的问题

原来的机器人装在**被监控的那台服务器自己身上**。这带来一个死结：

```
服务器流量超标 → 脚本把自己关机了（省钱 ✅）
              → 但脚本也一起死了
              → 下个月流量重置，没人去开机（复活 ❌）
```

我不是说它没用 —— **它省钱是真的**。但它救不了自己。你每个月都得手动去阿里云控制台点一次开机，忘了就一直停着。

### 这一套装的东西

把机器人搬到 **Cloudflare** 上跑。Cloudflare 是另一家公司的机房，跟你那台服务器没关系。

```
服务器流量超标 → 关机（省钱 ✅）
Cloudflare 上的机器人 → 它没跟着死，一直在跑
下个月流量重置 → 它发现机器还关着，自动开机（复活 ✅）
```

**这是唯一能真正解决死锁的办法。** 因为要叫醒一扇门里的人，你得站在门外。

### 花了多少钱

**免费。** Cloudflare 免费套餐的额度足够，但有一个**必须知道的容量红线**：

| 项目 | 免费额度 | 我们用掉 | 占比 |
|---|---|---|---|
| 定时任务触发 | 每天 10 万次 | 每天约 300 次 | 0.3% |
| 存储**读取** | 每天 10 万次 | 每天约 600 次 | 0.6% |
| 存储**写入** | **每天 1000 次** | 每天 **576 次** | **57.6%** ⚠️ |
| 存储**删除** | 每天 1000 次 | 基本不用 | — |
| 定时最小间隔 | 1 分钟 | 我们每 5 分钟一次 | — |

> **为什么写入是 576 次/天？**
> 巡检每 5 分钟跑一次（一天 288 次），每次固定写两次存储 ——
> 一次存巡检状态、一次存流量台账。288 × 2 = 576。
> 这个数字**与你有几台机器无关**（程序已做「一轮只写一次」优化），
> 所以 576 是恒定值，留了 42% 的余量。
>
> ⚠️ **超出任何一项额度，该类型的后续操作会直接报错**（每天 UTC 00:00 重置 =
> 北京时间早上 8 点）。我们已给写入加了容错：万一额度用尽，
> 巡检**不会崩溃**，只是当轮结果存不下来、下轮继续正常检查。

## 开始之前，先攒齐四样东西

按下表检查，缺哪样就先去办哪样。

### ⓪ 一台能上网的电脑（Windows 需要先装 Git Bash）

**Windows 用户**：先按下面第 0 步装好 Git Bash，否则启动器打不开菜单。
**Mac / Linux 用户**：系统自带终端，跳过这条。

### ① 一个 Cloudflare 账号

去 https://dash.cloudflare.com/sign-up 注册。邮箱 + 密码就行，不用绑卡。

### ② 一个 Telegram 机器人令牌

1. 在 Telegram 里搜索 **@BotFather**（注意是有官方认证标的那一个）
2. 发 `/newbot`
3. 它问名字，随便起，比如 `我的流量守护`
4. 它问用户名，**必须以 bot 结尾**，比如 `my_cdt_guard_bot`
5. 它会回一串令牌，长得像 `1234567890:AAHxxxxxxxxxxxxxxxxxxxxx`

**把这串令牌存好**，后面要用。

### ③ 你的 Telegram 数字 ID

1. 在 Telegram 里搜索 **@userinfobot**
2. 点「开始」
3. 它回你一条消息，里面 `Id:` 后面那串数字就是

这串数字的用途是：**只有你能操作机器人**，别人发消息它一个字都不回。

### ④ 阿里云的 AccessKey

去阿里云控制台 → 右上角头像 → 访问控制（RAM） → 用户 → 创建用户。

- 勾选「OpenAPI 调用访问」，它会给你 **AccessKey ID** 和 **AccessKey Secret**
- 权限至少要给：
  - `AliyunECSReadOnlyAccess`（查实例状态）
  - `AliyunECSSupportAccess` 或自定义含 `ecs:StartInstance` / `ecs:StopInstance` 的策略
  - `AliyunCDTReadOnlyAccess`（查流量）
  - `AliyunBSSReadOnlyAccess`（查余额账单）
- **Secret 只在创建时显示一次**，当场存好，关掉页面就再也看不到了

> 想省事的话，直接用主账号的 AK 也能跑。但**强烈建议用子账号**：万一泄露，损失可控。

## 部署

### 第 0 步：装 Git Bash（Windows 必装，Mac / Linux 跳过）

这套脚本要在 Git Bash 里跑，Windows 默认没这个环境。**不装的话双击启动器会直接告诉你缺什么**，但你可以现在就装好，省一趟来回。

1. 打开 https://git-scm.com/download/win
2. 网页自动开始下载。下完后双击安装包，**一路点 Next**（所有选项保持默认，一个都不用改）
3. 装完关掉窗口

**验证装好了没**：随便找一个文件夹 → 右键 → 菜单里应该出现「**Git Bash Here**」。

> 装过一次，以后永远不用再管。

**如果你更想用命令装**（需要 Windows 10 以上自带 winget）：

按 `Win + R`，粘贴下面这行，回车：

```
winget install --id Git.Git -e
```

装完同样用「右键能不能看到 Git Bash Here」验证。

### 第 1 步：双击启动器

解压安装包，进到文件夹里，找到 **`启动.bat`**：

**双击它就行。**

> **为什么不双击 `安装.ps1`？**
> Windows 对 `.ps1` 的默认动作是「用记事本打开」，不是「运行」。
> 双击 `安装.ps1` 只会弹出一屏代码，新手会以为工具坏了。
> `启动.bat` 是个垫片：`.bat` 双击会真的执行，它再自动去调 `安装.ps1`。
> （如果你偏爱 `.ps1`，也可以自己右键 → 使用 PowerShell 运行。）

它会做三件事：

1. 检查 `menu.sh` 在不在（不在会提醒你是不是多套了一层目录）
2. 自动在四个常见位置找 Git Bash（`Program Files\Git\bin\` 等），找不到就从 PATH 里的 `git` 反推
3. **找到就打开菜单；找不到就打印安装指引**（含 `winget` 命令和官网地址，还可以按 `y` 直接帮你打开下载页）

> **万一提示「在此系统上禁止运行脚本」**：这是 PowerShell 默认的安全策略。
> 打开 PowerShell 执行一次下面这行，输入 `Y` 回车，然后再右键运行启动器：
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

> **为什么启动器是 `.ps1` 不是 `.bat`**：cmd.exe 读 `.bat` 时按 GBK 解码，
> 而文件内容是 UTF-8 —— 中文会全部变成乱码，**乱码还会被当成命令去执行**
> （实测刷出一屏「不是内部或外部命令」）。PowerShell 原生支持 UTF-8，所以改用 `.ps1`。

如果你已经在 Git Bash 里，也可以直接：

```bash
cd 你存放这个项目的位置/cdt-guard-worker
bash menu.sh
```

打开就是这样一个中文菜单，**上面还写着当前状态**（不用猜现在装到哪一步了）：

```
 当前状态：
   Node.js        已装（v22.22.2）
   Cloudflare     已登录
   Worker         已部署  https://cdt-guard.xxx.workers.dev
   监控配置       已配 1 台机器 / 1 个账号

   1) 环境体检          检查缺什么、怎么装（第一次用先选它）
   2) 一站式安装        装好一切 + 配置机器，新手推荐
   3) 配置监控机器      重新填写要监控的机器（会覆盖旧配置）
   4) 添加阿里云账号    新增另一个账号，不动现有配置
   5) 查看当前配置      只读，不改任何东西
   6) 重新部署          代码改动后重新上传

   8) 重设网址密钥      密钥忘了、或想换一串时用
```

**第一次装：先选「1 环境体检」，再选「2 一站式安装」。**

#### 没装 Node.js 也能用（会问你要不要自动装）

不用去官网到处找下载链接 —— 直接选「1 环境体检」，
检出缺 Node 时会**问你一句「要不要现在自动装」**，输入 `y` 回车它就自己干活：

1. 自动读 https://nodejs.org/dist/index.json，挑当前最新的 LTS 版本
2. 按你的系统下载对应压缩包（Windows / macOS / Linux，x64 / arm64 自动认）
3. 解压到用户目录（`~/.cdt-guard-node`，**不污染系统、不需要管理员权限**）
4. 临时把它挂进 PATH，并**实测能不能跑通一段真实 JS** 再算成功

> ⚠️ 这里有两个容易踩的坑，脚本已经处理掉了，说给你听是让你放心：
>
> - **Windows 的 Node 压缩包里，`node.exe` 在根目录；Linux / macOS 在 `bin/` 下**。
>   加 PATH 的位置不一样，搞错就会出现「明明装了却说找不到」。
> - **`npm.cmd` 要和自己旁边的 `node_modules` 待在一起**，不能只把 `node.exe` 单独复制走，
>   否则 npm 直接报错。

自动装失败（比如网络不通）才会退回下面的兜底指引：

- **Windows**：给出 .msi 下载地址和 winget 命令
- **macOS**：给出 brew 命令和 .pkg 下载地址
- **Linux**：给出 apt / yum / nvm 三种方式

装完怎么验证（敲什么命令、看到什么算成功）也一并写清楚。

#### 没登录 Cloudflare 也能用（会拉起浏览器授权）

跑到部署那一步，如果检测到还没登录，会自动执行 `wrangler login`，
**浏览器自动打开一个授权页**，你点蓝色的「Allow / 允许」按钮即可。
页面显示成功就可以关掉，回到黑窗口继续。

想提前登录也行，在 Git Bash 里敲：

```bash
npx wrangler login
```

以前自检是让你自己复制一串网址到浏览器打开。现在**不用了** ——

[成功] Webhook 已设置

### 关于第 7 步：为什么「填机器」也在这一条命令里

**你问得对，这本来就该在一条命令里。** 我原来把「装程序」和「填配置」
拆成两个脚本，理由是「先确认程序能跑再填数据」——但这理由站不住脚：
**用户根本分不清这两步的区别，只觉得「怎么还没弄完」。**

而且更实际的问题：一键脚本跑到这里，你刚登录完 Cloudflare、注意力在线，
这时候顺口问机器信息是最省事的。让你再单独跑第二条命令，
意味着要重新回到电脑前、重新进入状态。

所以现在第 7 步会直接问你（每项都有说明）：

- 你的 Telegram 数字 ID
- 每台机器的：名字、实例 ID、地域、AK、SK、流量阈值

填完会**把配置展示给你看一遍**（密钥自动打码），确认无误才写入。

> **现在不想填也行**：第 7 步开头直接回车就跳过，以后随时补：
> ```bash
> bash configure.sh
> ```

```
  ├── ℹ️ 使用说明     │    ├── 🖥 菲律宾节点
  └── ❌ 收起菜单     │    ├── 🖥 新加坡节点
                      │    └── 🏠 返回主菜单
                      │
                      └──→ 第三层：单机操作
                           ├── 📊 状态   🚀 开机
                           ├── 🛑 关机   ⏸️ 暂停监控
                           ├── 🗑 删除机器
                           └── 🔙 返回列表  🏠 返回主菜单
```

### 常用命令（也可以直接打字）

| 命令 | 作用 |
|---|---|
| `/menu` | 打开菜单 |
| `/status` | 所有机器状态 |
| `/traffic` | 流量与免费额度 |
| `/balance` | 余额与账单 |
| `/accounts` | 按账号汇总 |
| `/creds` | 检查各账号访问密钥是否有效（凭据体检） |
| `/weekly` | 流量周报 |
| `/report` | 完整报表 |

| `/cancel` | 取消正在进行的「添加账号」流程 |
| `/help` | 使用说明 |

### 自动行为（不用你管）

| 什么时候 | 机器人做什么 |
|---|---|
| 每 5 分钟 | 查流量和状态；流量安全且机器停着 → 自动开机 |
| 流量超阈值 | 立刻强制关机止损，并通知你 |
| 流量用到 80% / 95% | 提前提醒你 |
| 余额低于警戒线 | 提醒你充值 |
| 机器被意外停机 | 立刻通知你（如果流量安全，会顺手开回来） |
| 每天早上 9 点 | 发一份完整报表 |
| 每天上午 10 点 | 自动做一次凭据体检，发现密钥失效才通知（正常时不打扰） |
| **访问密钥失效** | **立刻报一次**（告警自带「删除这台机器」按钮），7 天内不重复 |

> **关于「访问密钥失效」**：这是最危险的场景 —— 密钥坏了，监控就彻底瞎了，
> 流量跑超也没人管。所以它走**独立的告警通道**（不受普通 1 小时冷却压制），
> 首次立刻报。
>
> **告警里直接带两个按钮，点一下就处理完：**
> - **🗑 删除这台机器** —— 机器已经不用了 / 在阿里云上删掉了，点它摘掉，告警消失
> - **➕ 添加账号** —— 机器还在用，只是密钥过期了，点它重填一份有效凭据
>
> 为什么改成这样：以前是「每天提醒一次直到修好」。但如果那台机器**已经不在阿里云了**，
> 密钥就永远修不好 —— 告警会一天一次永远刷下去，你还没法让它停。
> 现在首次告警就给你「删掉它」的出口，点完彻底清净。
>
> 你也可以随时主动查：点菜单「**🔑 凭据体检**」或发 `/creds`。
>
> **🔴 删机器只删监控配置，绝不碰你的阿里云实例。** 删完机器人会明确回一句
> 「阿里云上的 ECS 实例本身没有被删除，记得去控制台释放以免继续计费」——
> 远程销毁一台机器是不可逆操作，不该由一个聊天按钮触发。
>
> **放心：密钥失效时机器人自己只告警、只标记，绝对不会自动删你的账号或机器配置。**
> 删不删由**你点按钮**决定，机器人只负责把选项摆到你面前。

### 「暂停监控」是什么意思

点「暂停监控」后，**脚本不再自动开关机**，但：

- 你手动点「开机」「关机」仍然有效
- 批量开关机**会跳过**它（尊重你不想让脚本碰它的意思）
- 流量超标也不会自动关机 —— 相当于「这机器我自己管」

再点一次「恢复监控」就回到自动模式。

## 常见问题

### Windows 双击启动器没反应 / 弹出记事本

**先确认你双击的是哪个文件**：请双击 **`启动.bat`**，不要双击 `安装.ps1`。

> Windows 对 `.ps1` 的默认动作是「用记事本打开」，不是「运行」。
> 这是系统行为，不是脚本的问题。`启动.bat` 就是为解决这一点准备的。

按可能性从高到低排：

| 现象 | 原因 | 解决 |
|---|---|---|
| 弹出的是记事本、满屏代码 | 双击了 `安装.ps1` | 改成双击 **`启动.bat`** |
| 窗口闪一下就没了 | 启动器报错了但没看清 | 用「右键 → 在终端中打开」，再敲 `启动.bat` 回车，就能看到完整信息 |
| 提示「禁止运行脚本」 | PowerShell 默认安全策略 | 执行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（输 `Y` 回车）后重试 |
| 提示「还差一个运行环境：Git for Windows」 | 没装 Git Bash | 照屏幕指引装（有 `winget` 命令和官网链接，按 `y` 可自动打开下载页） |
| 提示「No .ps1 launcher found」 | 解压时只拖出来一个文件 | 重新完整解压整个压缩包 |
| 提示「没找到 menu.sh」 | 解压后多套了一层目录 | 进到**最里面那层**再运行启动器 |
| 提示一堆「不是内部或外部命令」 | 用了含中文的旧 `.bat` 启动器 | 改用 `安装.ps1`（`.bat` 按 GBK 解码 UTF-8 会乱码并当命令执行） |

### 提示「查询失败」

一般是这几种原因：

- **AK 权限不够** —— 去阿里云检查那个子账号有没有放开机和查询权限
- **地域填错了** —— 实例在 `cn-hangzhou` 你填了 `ap-southeast-1`，查不到
- **实例 ID 写错** —— 少一位或大小写不对

机器人会**明确告诉你失败原因**，不会假装查到了 0。

> 填机器时脚本会先校验格式：实例 ID 必须是 `i-` 开头加小写字母数字，
> 地域必须是小写字母加短横线，阈值必须是正整数。**格式不对会当场拦住**，
> 并告诉你正确长什么样 —— 而不是等你配完才发现「怎么查不到数据」。

### 我还有一个阿里云账号，想一起监控

可以。**免费额度是按「账号」算的**（内地 20 GB / 非内地 200 GB），
所以多个账号一起监控，每个账号各算各的额度，互不占用。

#### 推荐做法：直接在手机上（Telegram 机器人里）加

不用打开电脑。在机器人菜单里点「**➕ 添加账号**」，然后跟着走：

```
你点「➕ 添加账号」
        ↓
机器人：说明这个流程要什么，等你发 AccessKey ID
        ↓
你发：AccessKey ID（LTAI 开头那串）
        ↓
机器人：格式没问题，存下了，等你发 AccessKey Secret
        ↓
你发：AccessKey Secret
        ↓
机器人：✓ 已删除你刚发的那条消息
        正在扫描这个账号下的机器……（分批并发，几秒钟）
        ↓
机器人：共找到 N 台机器
        1. 机器名 / 地域（中文名 + 代码）/ 状态 / 免费额度 / 实例 ID
        2. ……
        [✅ 全部加入监控] [🔄 重新扫描] [❌ 取消添加]
        ↓
你点「✅ 全部加入监控」
        ↓
机器人：✓ 已加入 N 台（新机器默认阈值 180 GB、默认开启监控）
```

几个设计上的取舍，说明一下：

- **为什么不用手填实例 ID / 地域**：机器人在扫的时候已经拿到了，没道理让你再抄一遍。
  扫到的机器会**全部自动配好**，你只需要点一下确认。
- **「只新增，不动现有」**：新账号的机器是**追加**进清单的，绝不会覆盖你现在监控的机器。
  已经监控过的实例 ID 会自动处理：凭据一样就跳过；**凭据换了（比如你换了新密钥）
  就原地更新**，不会多出一台，也不会把你改过的名字和阈值冲掉。
- **无名机器自动命名**：阿里云没给实例起名时，用「**中文地域 - 账号标识 - 机器尾号**」
  三段式命名，例如 `马尼拉-LTAI5t-sujw0r`。

  | 这一段 | 是什么 | 有什么用 |
  |---|---|---|
  | `马尼拉` | 地域中文名 | 一眼知道机器在哪个机房（不用记 `ap-southeast-6` 是什么） |
  | `LTAI5t` | 打码 AccessKey 的前 6 位 | 多账号时看出这台属于哪个账号（与「🏦 账号汇总」页显示的是同一套规则） |
  | `sujw0r` | 实例 ID 后 6 位 | 同地域同账号有多台时，靠它区分是哪一台 |

  扫描结果里的地域也会写成「中文名（代码）」两个都给：
  `地域 马尼拉（ap-southeast-6）` —— 中文名好认，代码查控制台/搜资料时有用。

  阿里云上如果你自己给实例起过名字，**就原样用你的名字**，不会套这个三段式。
- **15 分钟超时**：流程走到一半放下了，会话自动作废，不会一直挂在那里等你。

> **⚠️ 安全说明（重要，务必看一眼）**
>
> 在聊天窗口里发密钥，本身不是最安全的方式。为了让你能在手机上直接加账号，
> 我们做了这些事把它变得**足够安全**：
>
> 1. 收到 Secret 的那条消息**立刻删除**（你紧接着会看到「✓ 已删除」的回执）
> 2. 扫描期间密钥只存在**临时会话**里，**15 分钟自动过期**
> 3. 确认加入后密钥会写入机器人配置 —— **这一步是必须的**，
>    因为以后每次巡检都要用它向阿里云签名，不存就查不了
> 4. 任何展示（配置页面、回执消息）里的密钥**永远打码**，只露前 6 后 4
>
> 万一删除失败（Telegram 只允许删 48 小时以内的消息），机器人会**提醒你手动删**。
>
> 更稳妥的做法：给这个账号单独建一个 **RAM 子账号**，
> 只给「开机 / 关机 / 查询」权限，别直接用主账号的密钥。

#### 另一种做法：在电脑上跑脚本

电脑就在手边的话，菜单里选「**4 添加阿里云账号**」，走的是同一套扫描逻辑：

1. 先把你**现有的机器清单列出来**（让你放心：这个操作不会动它们）
2. 让你填新账号的 AccessKey
3. **自动去这个账号里把机器列出来**给你认 —— 不用去控制台手抄那串实例 ID
4. 逐台确认（新账号的 AK 会自动沿用，不用重复填）
5. 显示合并后的完整清单，确认后才写入

⚠️ **注意区分**：菜单里的「3 配置监控机器」是**覆盖**（重填一遍），
「4 添加阿里云账号」是**追加**（不动现有的）。脚本里也写清楚了，
按需选择。

> **如果填错了 AccessKey 会怎样？**

> 并列出常见原因。不会含糊地说「没扫到机器」让你瞎猜 ——
> 「Key 错了」和「这个账号真的没机器」是两回事，处理方式完全不同。

### 为什么不能用阿里云官方 SDK

Cloudflare Workers 跑在 V8 隔离环境里，不能装 node 的 SDK（依赖了 Node 的文件系统和原生模块）。

所以这里**手写了 RPC 签名**（HMAC-SHA1），用 Web Crypto API 实现。

### 一个坑：`SignatureType` 必须参与签名

阿里云的 RPC 签名里有个 `SignatureType` 参数，值为空字符串。

**这个看起来毫无意义的空参数必须参与签名计算** —— 少了它，签名不匹配，报 `SignatureDoesNotMatch`。

官方文档没强调这一点，实测对比过：
- 不含 → `1G1FVxj2al4acFg8+dsAK2wWuOM=` ❌
- 含（空值）→ `3sWYY1r9PaR1k3X/oi5n5hOEXNQ=` ✅

### 为什么收消息改成 Webhook

Workers 不能跑常驻进程，长轮询（`while True: getUpdates`）不可行。

改成 Webhook 后：你点按钮 → Telegram 主动 POST 到 Cloudflare → 处理完就结束。

这不是妥协 —— 这恰恰是无服务器环境的正确用法，而且**天然解决了「进程会死」的问题**。

### 存储为什么用 KV 而不是文件

Workers 没有磁盘。所有原本存文件的东西都搬进了 KV：

| 键名 | 存什么 |
|---|---|
| `config` | 机器清单、阈值、Chat ID |
| `state` | 上次告警时间、连续失败次数 |
| `traffic_history` | 流量台账（周报数据源） |
| `sessions` | 三级菜单「刚点的是哪台机器」 |

### 流量台账为什么按天去重

巡检每 5 分钟一次，一天 288 条 × 台数，全留会撑爆存储。

而周报看的是**每日趋势**，5 分钟精度没意义。所以同一台机器同一天只保留最新一条。

### 本地自检怎么跑

```bash
bash tests/run-all.sh
```

会跑 626 项检查（菜单文案 46 项 + 命令注册 14 项 + 集成 119 项
+ 添加账号流程 136 项 + 凭据失效处理 85 项 + 巡检回执 18 项
+ 机器身份定位 19 项 + 额度与阈值 36 项 + 部署脚本 125 项
+ 启动器 18 项），覆盖：

- emoji 转义是否正确（Python 的 `\U0001f4ca` 在 JS 里会变成字面文本！）
- 密钥遮蔽是否会死循环（踩过这个坑）
- Markdown 安全预判
- 台账去重语义
- 空配置不崩
- **删机器时不会误删其他机器**
- **免费额度按账号算，不按机器台数累加**（3 台海外机器只有 200GB，不是 600GB）
- **关机阈值填错时绝不关机**（`null` / `空串` / `abc` / 负数 都不能触发停机）
- **两台同名前缀的机器不会串台**（否则点「删除」会删错那一台）

- **凭据失效告警必须带「删除这台机器」按钮**

- **临时文件是否延迟创建**（只读操作不该留垃圾）

- **凭据错误分类准确**（密钥失效 vs 网络抖动，绝不能误报）
- **凭据失效时配置一个字节都不动**（这是最要紧的安全底线）

## 改了什么（本轮）

这一轮主要是**把「填机器」合并进了一键脚本**，外加修掉几处
「引用另一个脚本时会连带崩」的隐患：

| 改动 | 为什么 |
|---|---|
| 部署完直接接着问机器信息 | 用户分不清「装程序」和「填配置」，只觉得「怎么还没弄完」 |
| 配置逻辑统一收在 `run_configure()` | 原来两边各有一份，早晚会走偏（改一处忘一处） |
| 新增自动自检步骤 | 用户不用自己抄网址去浏览器打开 |
| 网址密钥存一份到本地 | 自动自检要用；它是自己编的，不是云厂商凭据 |
| 配置脚本的顶层 `exit` 收进函数 | 否则会把引用它的部署脚本一起杀掉 |
| 临时文件改为延迟创建 | 只读操作（`show`）不该留下垃圾文件 |
